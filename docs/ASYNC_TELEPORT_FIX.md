# 安全点搜索 Watchdog 与真正异步区块准备

## 原因

用户提供的 `crash-2026-11-15_09.17.34-server.txt` 显示主线程停在 `SafeTeleportService.tick:93 → ServerChunkCache.getChunkFuture → managedBlock`，Watchdog 随后停服。

旧实现取得 CompletableFuture 后跨 tick 检查 isDone，但 MC 1.21.1 的公开 getChunkFuture 在主线程调用时会先 managedBlock，直到加载完成才返回。因此仅保存 future 并不意味着提交动作非阻塞。不能用关闭 Watchdog 或把世界读写放到普通线程来掩盖此问题。

## 改动

- 新增 ServerChunkCacheAccessor，直接调用内部 getChunkFutureMainThread：只提交生成/加载任务并返回 future，不进入公开包装层的等待。
- TeleportChunkLoader 为每次准备添加独立 UUID 区块票据，准备落点周围 3×3 FULL 区块；future 全部成功且 getChunkNow 确认可用后，才进入安全地面、边界和碰撞检查。
- PendingChunkPreparation 跨 tick 轮询，无 join、阻塞 get 或忙等；检查 ChunkResult.isSuccess，避免把正常完成的失败结果当作加载成功。
- 取消、离线、超时、世界取消、加载失败、找不到安全点、余额不足及传送完成都会释放自有票据。关闭幂等；不取消可能被其他请求共享的区块 future。迟到的加载结果不会触发传送。
- 最多同时准备 4 个请求，每 tick 仍只处理一个搜索任务，避免多人 RTP 无限制提交生成任务。
- 原超时按“轮到玩家的次数”计数，现改为所有搜索每个实际 tick 都计龄，最多 1200 tick 或单调时钟经过 60 秒；取先到者。排队人数不会把超时成倍拖长。
- 安全验证、权限/世界代次复查、实际传送和成功扣费/冷却仍在服务端主线程。票据保留至传送及结算结束，再 finally 释放。

## 首轮修复范围（历史记录）

覆盖崩溃报告中的安全搜索队列：RTP、无已配置出生点时的安全选点、快捷维度旅行的对应坐标安全搜索与回退。没有修改版本、引入依赖或更改收费规则。

既有 `position` / `paidPosition` 定点传送布尔接口、已配置出生点的直接传送，以及其他模块的原版传送门/重生逻辑没有整体异步化；它们的调用者依赖即时成功结果和收费时机，不能简单改为异步排队后仍返回成功。本次不宣称已消除所有同步区块读取或所有 Watchdog 原因。

## 11:54 报告补修：定点传送与安全检查

新报告 `crash-2026-11-15_11.54.26-server.txt` 是 Watchdog，不是 OutOfMemoryError。栈为 `TeleportWarmupManager → GlobalPosInfo.teleport → SafeTeleportService.position → safe → getChunkBlocking`，属于首轮明确未改造的定点路径。报告当时堆使用为 1061MiB、已提交/上限 8192MiB；这不是当前进程/容器 10 多 GB 的完整统计，也不能代表此前峰值。

本轮将读条定点传送（家、上一位置、主城、领地/城镇、商店、死亡点等）、收费地标、TPA、已配置世界出生点以及原有内部救援/纠正调用迁入同一异步区块准备队列。RTP 与对应坐标搜索的首轮改动保留。

- 新 `GlobalPosInfo.teleportAsync` / `SafeTeleportService.queuePosition` 返回是否受理请求，而不是实际传送成功。现有同步 boolean 接口保留实际成功语义，未准备的区块直接拒绝，不悄悄排队后返回成功。
- 排队保存坐标、朝向和世界代次的独立快照，不跟随之后对配置对象的修改。定点落点不安全时拒绝，不擅自改成随机传送。
- 准备后重新校验权限、世界状态、代次、余额、移动/受伤，以及 TPA 另一方在线状态。普通请求仍可 `/tpcancel` 取消；实际成功才扣地标费用并执行成功提示，失败/取消不扣费。
- 内部救援、冻结/监禁纠正保存内部上下文，完成时用 `WorldManager.recover` 重新建立；相同内部请求不每秒重启加载。内部纠正沿用原强制传送语义，不套用普通移动/受伤中断。
- `position` 在安全检查/传送前确认周围 3×3 区块已就绪；`safe` 和 `safeColumn` 在方块/高度读取前用 `getChunkNow` 拒绝未加载区块，不因安全检查隐式同步加载。取消/超时/失败及完成仍释放自有票据。
